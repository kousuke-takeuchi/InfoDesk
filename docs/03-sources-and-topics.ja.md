# ソースとトピック

**ソース**は、InfoDesk が記事を集める場所です。各ソースは、固定の7つの**カテゴリー**のどれかに属します。**トピック**は、カテゴリーをまたいで記事をまとめる、名前付きのキーワードの一覧です。

## 1. 初期ソース

最初の起動で次のソースが入ります (2026-10-06 に確認)。どれも普通の行なので、無効にしたり、編集や削除をしたりできます。

| カテゴリー | ソース | 種類 |
|---|---|---|
| GitHub | GitHub Trending (日、週、月) | `github_trending` |
| arXiv | cs.AI、cs.CL、cs.LG | `arxiv` |
| Hugging Face | Trending Models、Daily Papers | `hf_models`、`hf_papers` |
| Hacker News | 上位記事 | `hackernews` |
| 国内tech | はてなブックマーク IT、Publickey、ITmedia、Zenn | `rss` |
| 海外tech | TechCrunch、The Verge、Ars Technica、MIT Technology Review | `rss` |
| 医療介護 | joint-kaigo.com、care-news.jp、Google News の検索 (認知症、介護、dementia) | `rss` |

CLI とデータベースで使うカテゴリー ID は `github`、`arxiv`、`huggingface`、`hackernews`、`tech_jp`、`tech_intl`、`medcare` です。

## 2. ソースの管理

**設定**を開き、**ソース**タブを選びます。

<picture>
  <img src="images/settings-sources.png" alt="設定のソースタブ。有効の切替、カテゴリー、状態を含むソースの一覧 (サンプルデータ)" width="720">
</picture>

*ソースタブ (サンプルデータ)。*

- トグルでソースを有効、無効にします。無効のソースは収集しません。
- 鉛筆で表示名とカテゴリーを編集します。設定値 (RSS ではフィードの URL) は表示されますが、変更できません。RSS の URL を変えたいときは、削除してから追加し直します。
- ごみ箱でソースを削除します。取得済みの記事は残ります。
- 各行に、最終取得の時刻と状態 (件数、エラー、無効) が出ます。

### RSS フィードの追加

1. **RSSを追加**を押します。
2. フィードの URL、表示名 (任意)、カテゴリーを入力します。
3. **追加**を押します。InfoDesk がフィードを1回取得して検証し、RSS または Atom として解析できたときだけソースを保存します。解析できなければダイアログにエラーを出し、何も保存しません。表示名が空なら、フィードのタイトルを使います。

追加したフィードは初期ソースと同じ扱いで、切替、編集、収集、要約の対象になります。

コマンドラインでは `infodesk source add-rss <URL> --category tech_jp` です。

## 3. トピック

トピックは名前とキーワードを持ちます。例: 名前「認知症」、キーワード「認知症」「dementia」「Alzheimer」。

<picture>
  <img src="images/settings-topics.png" alt="設定のトピックタブ。キーワードのチップと未読件数を含むトピックの一覧 (サンプルデータ)" width="720">
</picture>

*トピックタブ (サンプルデータ)。*

- **トピック**タブで**トピックを追加**を押し、名前とカンマ区切りのキーワードを入力します。
- 記事のタイトルか抜粋がキーワードのどれかに一致すると、その記事はトピックに属します。
- 英数字だけのキーワード (`AI`、`Rust` など) は、大文字小文字を区別せず、単語単位で照合します。`AI` は "again" に一致しません。それ以外のキーワードは部分一致で、2文字以下の語も照合します。
- 照合は検索のときに行うので、トピックの追加や変更は取得済みの記事にも反映されます。
- トピックはサイドバーに未読件数付きで並びます。選ぶと、フィードとダイジェストがそのトピックに絞られます。
- キーワードの変更やトピックの削除をすると、そのトピックの保存済みのダイジェストは削除されます。

CLI の例: `infodesk topic add 認知症 認知症 dementia Alzheimer`。

## 4. 記事の画像

新しい記事ごとに、収集のときに画像の URL を1回だけ決めて保存します。画像が決まらなかった記事は、画像なしのままです。既存の記事には遡って付けません。サムネイルは[フィード](05-feed-and-reader.ja.md)に、カードは[ダイジェスト](04-digests.ja.md)に出ます。

画像は次の順で決めます。

1. **RSS と Atom**: エントリーの Media RSS のサムネイル、画像の Media RSS コンテンツ、画像の enclosure。
2. **GitHub Trending**: リポジトリ所有者のアバター (`https://github.com/<owner>.png`)。追加の通信はしません。
3. **ページの取得**: それでも無ければ、記事のページを取得して `og:image` (なければ `twitter:image`) を読みます。

arXiv の記事と、Google News の転送 URL (`news.google.com`) の記事は、ページを取りに行かず、画像なしです。

ページの取得には次の上限があります。

| 項目 | 値 |
|---|---|
| 同時の取得数 | 4 |
| 1ページの制限時間 | 10秒 |
| 1ページで読む量 | 先頭の 512 KB |
| 1回の収集での時間枠 | 60秒 (終わらなかったページは取りません) |
| たどるリダイレクト | 最大 5 回 |
| アドレス | プライベート、ループバック、ローカルのアドレスは拒否 |
| 画像の URL | `https` のみ。ユーザー情報なし、2048 文字以内。相対 URL はページの URL を基準に解決 |

取得の失敗が記事の保存を妨げることはなく、収集のエラーとしても記録しません。ページの取得があるため、収集では新しい記事のサイトに、この Mac から接続します。画像は表示のたびに元のサイトから読み込みます。詳しくはプライバシーのページを参照してください。

## 5. 収集のスケジュール

収集はタイマーと手動で動きます。

- **間隔**: 既定は3時間おき。スケジュールタブでは 1分、5分、15分、30分、1時間、3時間、6時間、12時間から選べます (`schedule.collect_interval_minutes`、1〜10080分)。スケジューラーは15秒ごとに確認します。旧設定の `schedule.collect_interval_hours` は、分の設定がないときだけ読みます。起動時に、アプリはこの値から分の設定を作ります。
- **今すぐ収集**: フィードの空の画面、スケジュールタブ、メニューバーから。
- **収集のたび**: 各カテゴリーの上位の記事に要約を付け (既定は1カテゴリー20件、`summary.top_n`)。収集では、どの要約も作り直しません。
- **日次**: 07:00 に前日の要約を確定します (`schedule.daily_time`)。今日の要約は、「生成」または「再生成」を押したときだけ作ります。
- **週次**: 月曜 07:30 に前週の要約を作ります (`schedule.weekly_day`、`schedule.weekly_time`)。
- **月次**: 毎月1日の 08:00 に前月の要約を作ります (`schedule.monthly_time`)。

実行されなかったジョブ (Mac がスリープしていた、アプリを閉じていたなど) は、次にアプリが起動または復帰したときに1回だけ補います。時刻はすべてローカルの時刻です。
