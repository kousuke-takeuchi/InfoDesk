# プライバシーとセキュリティ

InfoDesk は、1人で使うデスクトップアプリです。アカウントも、専用のサーバーもありません。このページでは、Mac の中に残るもの、ネットワークへ出るもの、設けてある保護を挙げます。コードを検索したところ、解析やテレメトリのライブラリは見つかりませんでした。

脆弱性を報告するときは [SECURITY.md](../SECURITY.md) を見てください。

## Mac の中に残るもの

- DB `~/Library/Application Support/jp.infodesk.app/infodesk.db` に、ソース、トピック、収集した記事、要約、ダイジェスト、チャットのスレッド、設定が入ります。
- InfoDesk のサービスへは何もアップロードしません。そのようなサービスはありません。
- 同じ Mac の Ollama を使うとき、要約、ダイジェスト、チャットはローカルで動きます。そのための記事の文章はマシンの外へ出ません。
- チャットのツールは読み取り専用で、この DB ([CLI](08-cli.ja.md) 経由) と、許可したページや検索 (下記) だけを読みます。

## ネットワークへ出るもの

| 内容 | 送り先 | いつ |
|---|---|---|
| フィードとソースの API | 有効なソース (組み込みと、追加した RSS) のホスト | 収集のたび |
| 記事のページ (`og:image` 用) | その記事のサイト | 収集時に、フィードの画像がない新着記事について。1ページ最大512 KiB、タイムアウト10秒、同時4件、1回の収集で合計60秒まで |
| 記事の画像 | 画像のホスト | サムネイルやカードを表示するとき。ウィンドウが `https:` から直接読みます |
| Ollama での LLM の文章 | `ollama.base_url` の URL (既定は `http://localhost:11434`) | 要約、ダイジェスト、チャット |
| Claude での LLM の文章 | Anthropic。導入してログインした `claude` CLI 経由 | Claude を選んだときの要約、ダイジェスト、チャット |
| チャット用の記事本文 | その記事の URL | エージェントが `fetch_page` を呼んだときだけ。保存しません |
| チャット用の Web 検索 | Claude: 組み込みの WebSearch。Ollama: `https://ollama.com/api/web_search` | エージェントが Web を検索したときだけ。Ollama では API キーを設定したときだけ |

補足:

- `ollama.base_url` を別のマシンにすると、文章はそのマシンへ送られます。既定はローカルです。
- Claude を使うと、要約とダイジェストでは記事のタイトルと概要、チャットでは質問とツールの結果が送られます。私的な資料を送る前に、CLI について Anthropic の規約を確かめてください。InfoDesk は、セッションを残さない設定で CLI を起動します。
- 記事を閲覧ウィンドウで開くと、ブラウザーと同じようにそのサイトを読み込みます。サイトにはあなたの訪問が見えます。
- リクエストは `InfoDesk/0.1` と名乗ります。

## 保存している秘密情報

InfoDesk が保存する秘密情報は、任意の ollama.com の API キー (`ollama.web_search_api_key`) だけです。SQLite の設定テーブルに平文で保存し、`infodesk config list` でも表示されます。DB のファイルを読める人は、キーも読めます。ユーザーアカウントのファイルの権限を非公開に保ち、DB や `config list` のスクリーンショットを共有しないでください。

Claude は CLI 経由で使うので、InfoDesk は Claude の認証情報を保存しません。

## ページ取得の保護 (SSRF)

チャットと CLI は、記事の文章に書かれた URL を取得できます。モデルがその URL をたどることがあります。内部のアドレスを取得させる文面が通ってはいけません。そのため `crates/core/src/page.rs` は、`fetch_page`、`infodesk page`、`og:image` の取得に次の規則を適用します。

- `http` と `https` の URL だけ。
- アドレスは名前解決の時点で検査します。プライベートなアドレスを指す DNS 名は拒みます。IP リテラルと `localhost` 系の名前は、接続の前に検査します。
- 拒むアドレス: ループバック、プライベート、リンクローカル、未指定、マルチキャスト、ブロードキャスト、`0.0.0.0/8`、キャリアグレード NAT の `100.64.0.0/10`、IPv6 のユニークローカル `fc00::/7` とリンクローカル `fe80::/10`。IPv4 射影の IPv6 アドレスは IPv4 として扱います。
- リダイレクトのたびに再検査し、回数は最大5回です。
- 読むのは最大2,000,000バイト、タイムアウトは30秒です。本文のテキストは文字数の上限で切ります。
- 取得したページの本文は DB に保存しません。

この保護は、エージェントと CLI の取得に対するものです。フィードの収集は、設定したソースを取得します。

## 閲覧ウィンドウの分離

アプリ内の閲覧ウィンドウは、記事をアプリの中で表示します。外のページがアプリ自身の権限に触れないように作ってあります。

- 閲覧ウィンドウには2つの WebView があります。ツールバー (アプリのページ) と記事のページです。`app/src-tauri/capabilities/default.json` に載っているのは、メインウィンドウとツールバーの WebView だけです。記事の WebView には権限がないので、その中のページはアプリの IPC コマンドを呼べません。
- このファイルがアプリ自身のページに与える権限は、`core:default`、`core:event:default`、ウィンドウの表示、非表示、フォーカス、`opener:default`、`autostart:default` です。
- 閲覧ウィンドウが開くのは `http` と `https` の URL だけで、手元のホストは拒みます。`localhost` と `*.localhost`、ループバック、プライベート、リンクローカル、未指定、マルチキャストのアドレスです。これらはアプリ自身のオリジンと重なり得て、読み込むとそのページが IPC を使えてしまうからです。閲覧ウィンドウの中の移動にも同じ検査をします。
- 新しいウィンドウを開こうとするページは拒みます。行き先が許可されるものなら、代わりにその場で移動します。
- ローカルや LAN の記事リンクは、閲覧ウィンドウではなく既定のブラウザーで開きます。
- チャットの回答の中のリンクは、`http` と `https` だけを閲覧ウィンドウで開きます。回答の中の画像は読み込みません。

## コンテンツセキュリティポリシー (CSP)

アプリのページは、次のポリシーで動きます (`app/src-tauri/tauri.conf.json`)。

```
default-src 'self'; connect-src ipc: http://ipc.localhost http://127.0.0.1:*; img-src 'self' data: https:; style-src 'self' 'unsafe-inline'; font-src 'self' data:
```

- スクリプトなどは、既定ではアプリ自身のファイルだけです。
- アプリのページからのネットワーク要求は、Tauri の IPC と `127.0.0.1` (チャットのエージェント) だけに行けます。
- 画像は、記事のサムネイルのために `https:` のホストから読めます。チャットの回答が画像を落とすのはこのためです。回答の中の外部画像は、表示するだけで要求が出てしまいます。

## チャットのエージェント (サイドカー)

チャットは、アプリが起動する別の Node プロセスで動きます。公開サーバーではありません。

- `127.0.0.1` だけで待ち受け、ポートは起動時に空きを選びます。
- アプリは、サイドカーを起動するたびにランダムな16バイトのトークン (16進32文字、`/dev/urandom` から取得) を作り、サイドカーとアプリのページへ渡します。すべての要求に `Authorization: Bearer <token>` が必要です。比較は一定時間で行います。トークンが違う、またはなければ 401 です。
- CORS で許すオリジンは `tauri://localhost` と `http://localhost:1420` (開発サーバー) だけです。ほかのオリジンからの要求は 403 です。
- 用意しているのは `GET /health` と `POST /chat` だけです。5 MiB を超える本文は拒みます (413)。不正な本文は 400 です。
- サイドカーは、アプリの DB に対して `infodesk` CLI を実行してデータを読みます。書き込みのツールはありません。
- アプリが終了または異常終了すると、サイドカーの標準入力が閉じ、サイドカーも終了します。

## 限界のまとめ

- API キーは平文で保存されます (上記)。
- プロンプトインジェクションは完全には防げません。[AI チャット](06-ai-chat.ja.md)を参照してください。
- 記事を開く、画像を読み込むと、第三者のサイトに接続します。
- このアプリは macOS 向けのアルファ版です。外部のセキュリティレビューは受けていません。
