# InfoDesk 設計書

日付: 2026-10-06
状態: レビュー待ち

## 1. 目的

技術系と医療介護系の情報を1つのデスクトップアプリに自動で集め、日次、週次、月次の日本語要約で把握できるようにする。利用者は本人1名。ダイジェストを読む使い方と、記事一覧を自分で絞り込んで読む使い方の両方を主機能とする。

### 成功条件

- アプリを開くと、当日のカテゴリー別要約がすでに生成されている。
- 記事一覧をカテゴリー、トピック、期間、ソースで絞り込める。
- 設定画面からRSSフィードを追加でき、追加したフィードは次回の収集から記事一覧と要約に反映される。
- 要約はローカルLLMだけで完結でき、設定でClaudeに切り替えられる。
- ウィンドウを閉じても収集と要約生成が続く。

### 対象外 (初版)

- 複数ユーザー、同期、モバイル対応
- `bge-m3` による意味検索 (キーワード照合で不足した場合に追加を検討する)
- 収集時の記事本文の取得 (収集ではフィードやAPIが返すタイトルと概要のみを扱う。本文はチャットでエージェントが必要とした記事に限り取得する。12節)
- プッシュ通知
- Windows、Linux対応 (macOSのみ)

## 2. 前提環境

- macOS、Apple M2 Max、メモリ32GB
- Ollama 0.34.2。導入済みモデルは `gemma4:26b` と `bge-m3`
- Rust 1.97、Node 26
- `claude` CLI 2.1.285

## 3. 構成

Tauri 2を使う。バックエンドはRust、UIはReact + TypeScript。

```
UI (React)
  │ Tauri command / event
  ▼
Rust バックエンド
  ├─ collector   ソースから記事を取得する
  ├─ store       SQLiteへの読み書き
  ├─ summarizer  LLMで要約を生成する
  └─ scheduler   収集と要約を定期実行する
```

各部品の責務と依存は次のとおり。

### collector

- 責務: 1つのソースから記事を取得し、共通の `Item` 型に正規化して返す。
- インターフェース: 関数 `fetch_source(http, source)` が `Vec<NewItem>` を返す。ソースの種類 (`SourceKind`) で取得器に振り分ける。
- 実装: `github`、`hackernews`、`huggingface`、`feed` (RSS、Atom、arXiv) の各モジュール。
- 依存: HTTPクライアントのみ。storeには依存しない。保存は呼び出し側が行う。
- `Rss` は汎用実装で、フィードURLとカテゴリーを引数に取る。国内tech、海外tech、医療介護のニュースと、利用者が追加したフィードはすべてこの実装を使う。

### store

- 責務: 記事、要約、トピック、ソース設定、アプリ設定の永続化と検索。
- 実装: SQLite。記事のタイトルと概要にFTS5の全文検索を張る。日本語を扱うためトークナイザーはtrigramとする。
- 重複排除: 記事はURLを一意キーとする。同じURLを再取得した場合は、スター数などの指標だけ更新する。

### summarizer

- 責務: 記事要約と期間要約を生成する。
- インターフェース: trait `LlmProvider`。`complete(prompt)` が文字列を返す。
- 実装: `OllamaProvider` (ローカルHTTP API、既定モデル `gemma4:26b`) と `ClaudeProvider` (`claude` CLIのヘッドレス実行)。
- 依存: storeと `LlmProvider`。プロバイダーは設定から選ぶ。

### scheduler

- 責務: 収集と要約を決まった時刻に起動する。メニューバー常駐を管理する。
- 既定のスケジュール: 収集は3時間おき。日次要約は毎朝7時。週次要約は月曜の朝。月次要約は毎月1日の朝。時刻と間隔は設定で変更できる。
- 起動時に、停止していた間に実行されなかった収集と要約を補う。

## 4. ソースとカテゴリー

カテゴリーは7つで固定する。各ソースは1つのカテゴリーに属する。

| カテゴリー | 初期ソース | 取得方法 |
|---|---|---|
| GitHub | trending (日、週、月) | 公式APIがないため、実装計画で方法を検証する |
| arXiv | cs.AI、cs.CL、cs.LG など (選択式) | 公式API |
| Hugging Face | trendingのモデルと論文 | 実装計画でAPIを検証する |
| Hacker News | 上位記事 | 公式API |
| 国内tech | はてなブックマークIT、Publickey、ITmedia、Zenn | RSS |
| 海外tech | TechCrunch、The Verge、Ars Technica、MIT Technology Review | RSS |
| 医療介護 | joint-kaigo.com、care-news.jp、Google News検索 (認知症、介護、dementia) | RSS |

この表のソースは2026-10-06に取得と解析を確認した。CBnews、ケアマネタイムス、PubMedは固定のRSS URLがないため初期ソースから外し、Google News検索のRSSで代替した。

### RSSフィードの追加

利用者は設定画面からRSSフィードを追加、編集、削除できる。

- 入力項目: フィードURL、表示名、カテゴリー (7つから選択)。
- 追加時にフィードを1回取得して検証する。RSSまたはAtomとして解析できない場合はエラーを表示し、保存しない。
- 表示名は空欄でもよい。その場合はフィードのタイトルを使う。
- 追加したフィードは初期ソースと同じ扱いになり、有効と無効の切替、収集、要約の対象になる。
- 初期ソースのRSSも同じテーブルに初期データとして入れる。利用者が追加したものと区別なく編集と削除ができる。
- フィードを削除しても、取得済みの記事は残す。

## 5. トピック (キーワード)

- 利用者は「トピック」を登録する。トピックは名前とキーワードの一覧を持つ。例: 名前「認知症」、キーワード「認知症」「dementia」「Alzheimer」。
- 記事がトピックのキーワードのいずれかにFTS5で一致した場合、その記事はトピックに属する。
- 記事一覧とダイジェストの両方を、トピックで絞り込める。
- トピックの追加と変更は、取得済みの記事にも遡って適用される (照合は検索時に行う)。キーワードを変更またはトピックを削除すると、そのトピックの期間要約は削除される。
- 英数字だけのキーワード (例: AI、Rust) は単語単位で照合する (AI は again に一致しない)。それ以外は部分一致。

## 6. 要約

### 記事要約

- 収集のたびに、各カテゴリーの上位N件 (既定20件) に日本語1〜2文の要約を付ける。英語の記事は和訳を兼ねる。
- 上位の基準はソースごとの指標 (スター増加数、HNのポイントなど) とする。指標のないRSSは新着順とする。
- 全件は処理しない。ローカルLLMの処理時間を抑えるためである。

### 期間要約

階層式で生成する。

- 日次: カテゴリーごとに、当日の記事のタイトルと記事要約を入力とする。
- 週次: カテゴリーごとに、その週の日次要約を入力とする。
- 月次: カテゴリーごとに、その月に重なる週 (月初を含む週から月末を含む週まで) の週次要約を入力とする。月の境界をまたぐ週は両方の月に入る。

各期間要約には、根拠にした記事へのリンクを付ける。該当期間に記事がないカテゴリーは要約を生成しない。

### トピック別要約

ダイジェスト画面でトピックと期間を選んだ時に、その場で生成する。入力は該当記事のタイトルと記事要約。生成結果は保存し、同じ条件では再利用する。

### プロバイダー

- 既定はOllama。設定画面でClaudeに切り替えられる。
- Claudeは初版では `claude` CLIのヘッドレス実行を使う。APIキーの管理を不要にするためである。使うフラグは実装計画で `claude --help` と公式ドキュメントから確認する。
- 設定画面で、記事要約と期間要約に別のプロバイダーを割り当てられる。件数の多い記事要約はOllama、月次要約はClaude、という使い分けを想定する。

## 7. 画面

デザインは `design.pen` で確定した (2026-10-06)。書き出しは `design/exports/` にある。実装はこのデザインに従う。

### 共通

- ウィンドウの基準サイズは 1200 x 800。左にサイドバー (幅220)、右にメイン。チャットを開くとメインの右に幅400のパネルが付く。
- 外観はライトとダークの両方を持ち、macOSの設定に追従する。書体はmacOSのシステムフォント。
- デザイントークン (`design.pen` の変数): 背景 `bg-window`、`bg-sidebar`、`bg-subtle`。線 `border`。文字 `text-primary`、`text-secondary`、`text-tertiary`。強調 `accent`、`selection`、`on-accent`。状態 `success`、`danger`、`star`。部品 `seg-selected`、`toggle-off`。角丸 5 と 7。文字は本文13px、補足11〜12px、画面見出し22px、節見出し15px。
- サイドバー: 「すべて」、カテゴリー7件、トピックの一覧。各行に未読件数。左下に収集状態 (最終収集時刻、収集中の進行) と「設定」。サイドバーの選択がダイジェストとフィードの範囲になる。
- ツールバー: 左にダイジェストとフィードの切替。右に画面ごとの絞り込みと検索、チャットの開閉ボタン。

### ダイジェスト (A-1、A-10)

- 期間は今日、週、月の切替。見出しに期間の日付と「再生成」。
- サイドバーで「すべて」またはカテゴリーを選ぶとカテゴリー別の要約、トピックを選ぶとトピック別の要約を表示する。
- 各要約は、カテゴリー名、生成元 (プロバイダー名) と記事数、箇条書きの本文 (幅720px)、根拠記事のリンクで構成する。
- 状態: 生成中、保留 (理由と次回の再試行時刻、「今すぐ再試行」)、失敗 (回数と最後のエラー、「再試行」)、記事なし。状態は要約ごとに表示し、他の要約に影響しない。

### フィード (A-2、A-11)

- 記事行: 未読の青丸、タイトル (未読は太字)、ソース名、相対時刻、指標 (ある場合)、記事要約 (1〜2行)、スター。
- 絞り込み: 期間、ソース、未読のみ、スターのみ、フリーワード検索。見出しに未読件数と「すべて既読にする」。
- 記事をクリックすると既定のブラウザで開き、既読になる。行のホバーまたは右クリックで「チャットで質問」を出す。
- 初回起動 (未収集) は空状態を表示し、「今すぐ収集」と「ソースを確認」を置く。

### 設定 (A-3、A-5、A-6、A-7、A-8)

メインウィンドウ内に表示し、ソース、トピック、LLM、スケジュールのタブで切り替える。

- ソース: 一覧 (有効切替、名前とURL、カテゴリー、最終取得、状態 (件数、エラー内容、無効)、編集、削除)。「RSSを追加」のダイアログは URL、表示名 (任意)、カテゴリーを入力し、検証中、検証OK (タイトルと件数)、検証エラーを表示する。検証OKのときだけ「追加」を押せる。
- トピック: 一覧 (名前、キーワードのチップ、未読件数、編集、削除) と編集カード (名前、カンマ区切りのキーワード)。
- LLM: 記事要約、期間要約、チャットの既定プロバイダーをそれぞれ選ぶ。Ollama はURL、モデル、接続テスト、Web検索APIキー。Claude は `claude` のパスと接続テスト。チャット用に Node のパス。
- スケジュール: 収集間隔と次回の収集 (「今すぐ収集」)、日次、週次、月次の要約時刻、ログイン時に起動、ウィンドウを閉じても常駐する、保留中の要約の一覧と「今すぐ再試行」。

### チャットパネル (A-4、A-12)

12節を参照。上から、スレッド名と操作 (新規、履歴、閉じる)、文脈チップ、メッセージ、入力欄 (モデル選択、送信)。状態は空 (質問例)、LLMエラー (再試行、別プロバイダーで送る、設定)、サイドカー停止 (Nodeのパス設定)。

### メニューバー (A-9)

状態行 (最終収集時刻と記事数、未読件数と日次要約の状態)、今すぐ収集、ウィンドウを開く、設定、終了。ウィンドウを閉じてもアプリは終了せず、メニューバーに残る (設定で変更可)。

## 8. データモデル

- `sources`: id、種類 (github、arxiv、huggingface、hackernews、rss)、表示名、カテゴリー、URLまたは設定値、有効フラグ、最終取得時刻、最終エラー
- `items`: id、source_id、URL (一意)、タイトル、概要、著者、公開日時、取得日時、指標、記事要約、既読フラグ、スターフラグ
- `items_fts`: `items` のタイトルと概要に対するFTS5の仮想テーブル
- `topics`: id、名前、キーワード一覧
- `digests`: id、期間種別 (日、週、月)、期間の開始日、カテゴリーまたはトピック、本文、根拠記事のid一覧、プロバイダー名、状態 (保留、生成済み、失敗)、生成日時
- `settings`: キーと値。主なキー: `llm.items_provider`、`llm.digest_provider`、`llm.chat_provider`、`ollama.base_url`、`ollama.model`、`ollama.web_search_api_key`、`claude.bin`、`node.bin`、`summary.top_n`、`schedule.collect_interval_hours`、`schedule.daily_time`、`schedule.weekly_day`、`schedule.weekly_time`、`schedule.monthly_time`、`app.launch_at_login`、`app.stay_resident`

## 9. エラー処理

- 収集の失敗はソース単位で隔離する。1つのソースが失敗しても、他のソースの収集は続ける。失敗の内容は `sources` に記録し、設定画面に表示する。次回の収集で再試行する。
- LLMが応答しない場合 (Ollamaが未起動など)、要約は「保留」として残し、次回のスケジュール実行で再試行する。ダイジェスト画面には保留中であることを表示する。
- Claudeが選択されていて失敗した場合、Ollamaへの自動切替は行わない。利用者が選んだプロバイダー以外に内容を送らないためである。
- RSSの追加時に検証が失敗した場合は、保存せずにエラーを表示する。

## 10. テスト

- collector: ソースごとに、保存した実レスポンスをフィクスチャとして、パーサーを単体テストする。ネットワークには接続しない。
- store: インメモリのSQLiteで、重複排除、絞り込み、FTS5によるトピック照合 (日本語と英語) をテストする。
- summarizer: モックの `LlmProvider` で、階層式の入力組み立て、保留と再試行、記事なしの場合の省略をテストする。
- RSS追加: 正常なRSS、正常なAtom、不正な内容、到達不能の各場合をテストする。
- UI: 絞り込み条件の組み立てなど、ロジックを持つ部分だけを単体テストする。
- 実際のOllamaとの結合は、手動の動作確認とする。

## 12. チャット (エージェント)

### 目的

収集した記事と要約について、エージェントに質問して要約や調査をさせる。例: 「今週の認知症関連の動きをまとめて」「この記事を詳しく要約して」「このリポジトリと似たものを探して」。

### 画面

- ダイジェストとフィードの右側に、開閉式のパネルとして表示する。ツールバーのボタンで開閉する。
- 表示中のカテゴリー、トピック、期間を文脈として質問に付ける。記事行と要約からは「チャットで質問」でその記事や要約を文脈に追加できる。
- エージェントの回答はストリーミングで表示する。ツールの実行 (検索中、本文取得中など) を回答の中に表示する。回答が参照した記事はリンクで示す。
- 会話はスレッドとして保存する。パネル上部でスレッドの一覧、切替、新規作成、削除ができる。
- パネル内でLLM (OllamaまたはClaude) を切り替えられる。

### 採用するオープンソースライブラリ

2026-10-06 に npm と公式ドキュメントで確認した。

| 役割 | ライブラリ | 版 | ライセンス |
|---|---|---|---|
| チャットUI | `@assistant-ui/react`、`@assistant-ui/react-ai-sdk` | 0.15.23、1.4.14 | MIT |
| エージェント実行 | `ai` (Vercel AI SDK)、`@ai-sdk/react` | 7.0.128、4.0.131 | Apache-2.0 |
| Ollama接続 | `ai-sdk-ollama` | 4.4.0 | MIT |
| Claude接続 | `ai-sdk-provider-claude-code` | 4.3.3 | MIT |

選定理由と制約は次のとおり。

- assistant-ui は React 用のチャット部品群で、ストリーミング、Markdown、ツール呼び出しの表示、スレッド一覧を持つ。AI SDK v7 の公式アダプターがある。
- AI SDK の `ToolLoopAgent` がツール呼び出しのループを実行する。
- `ai-sdk-provider-claude-code` は Claude Code CLI を使うため、Node 22 以上のプロセスで動かす必要がある。AI SDK の `tools` は無視されるため、`createAiSdkMcpServer` でツールを橋渡しする。ツールは `execute` を持つ必要があり、UI側で実行するツールは使えない。
- 不採用: CopilotKit (独自ランタイムのサーバーが前提)、chatscope (2025-05 以降更新なし、ストリーミングとツール表示がない)、Mastra と LangGraph.js (単一エージェントには過剰)、rig (Rust、UIとの接続を全て自作する必要がある)。

### 構成

```
UI (assistant-ui)
  │ HTTP (127.0.0.1、AI SDK の UI message stream)
  ▼
エージェントプロセス (Node、サイドカー)
  ├─ ToolLoopAgent + ai-sdk-ollama            … Ollama を使う場合
  ├─ ai-sdk-provider-claude-code + MCP 橋渡し … Claude を使う場合
  └─ ツール → `infodesk` CLI (JSON出力) → SQLite
```

- エージェントは Node のサイドカープロセスで動かす。Ollama と Claude の両方を同じプロセスで扱い、ツールの実装を1つにするためである。
- サイドカーは Tauri アプリが起動し、127.0.0.1 の空きポートで待ち受ける。アプリの終了時に停止する。
- Node は利用者の環境のもの (26) を使う。実行ファイルのパスは設定 `node.bin` で変更できる。アプリには同梱しない。
- ツールは `infodesk` CLI を JSON 出力で呼び出す。絞り込みとキーワード照合のロジックを core に一本化するためである。

### ツール

| ツール | 内容 | 実装 |
|---|---|---|
| 記事検索 | 収集済みの記事を、キーワード、カテゴリー、トピック、期間で検索する | `infodesk items --json` |
| 期間要約の参照 | 生成済みの日次、週次、月次の要約を読む。生成はしない | `infodesk digest show --json` |
| 記事本文の取得 | 記事のURLを取得し、本文のテキストを返す。長さに上限を設ける | `infodesk page <url>` |
| Web検索 | 収集した記事の外を検索する | Claude: 組み込みの WebSearch。Ollama: Ollama の Web検索API (APIキーが必要) |

- Web検索は外部サービスに問い合わせる。Ollama では、設定にAPIキーがある場合だけツールを有効にする。
- 記事本文の取得は、エージェントが要求したURLに限る。取得した本文はDBに保存しない。

### データモデルの追加

- `chat_threads`: id、タイトル、作成日時、更新日時
- `chat_messages`: id、thread_id、役割 (user、assistant)、内容 (AI SDK のメッセージ形式のJSON)、作成日時

### エラー処理

- サイドカーが起動できない (Node がない、ポートを確保できない) 場合、チャットパネルに原因と設定への導線を表示する。ダイジェストとフィードは影響を受けない。
- LLM が応答しない場合、パネルにエラーと再試行のボタンを表示する。入力済みの質問は消さない。
- ツールが失敗した場合、その失敗をエージェントに返し、回答の中に表示する。

### テスト

- ツール: CLI の JSON 出力を、インメモリまたは一時DBで単体テストする。本文取得は wiremock でテストする。
- サイドカー: モックのモデルで、ツール呼び出しのループとストリームの形式をテストする。
- チャットの保存: スレッドとメッセージの保存、一覧、削除を単体テストする。
- 実際の Ollama と Claude での会話は、手動の動作確認とする。
