# InfoDesk 画面設計フェーズ (Phase 0)

**Goal:** 実装の前に、pen (pencil MCP、`.pen` ファイル) で全画面を設計し、利用者の確認と調整を経てデザインを確定する。

**Spec:** `docs/superpowers/specs/2026-10-06-infodesk-design.md` の7節 (画面)

**位置づけ:** このフェーズは Plan 1 (`2026-10-06-infodesk-core.md`) と Plan 2 (Tauriアプリ) の前に行う。確定したデザインは Plan 2 の入力になる。デザインの確認でデータ項目や機能が変わった場合は、Plan 1 の実行前に spec と Plan 1 に反映する。

## 制約

- `.pen` ファイルは pencil MCP のツールだけで読み書きする。Read や Grep で直接開かない。
- 作業の最初に pencil MCP のスキルとスキーマの説明を読み、ツールの入力仕様に従う。
- 文言は日本語。対象はmacOSのデスクトップウィンドウ。
- 画面に載せる情報は spec 8節のデータモデルにある項目に限る。足りない項目が必要になった場合は、デザインに入れる前に利用者に確認する。
- 各ステップの終わりで利用者の確認を取る。承認なしに次のステップへ進まない。

## 成果物

- `design.pen`: 全画面と状態のデザイン
- `design/exports/`: 各フレームの画像 (確認と Plan 2 の参照用)
- spec 7節の更新: 確定したレイアウト、デザイントークン (色、文字、余白)、画面ごとの構成要素

## 対象フレーム

| フレーム | 内容 |
|---|---|
| ダイジェスト | 今日 / 週 / 月のタブ、カテゴリー別の要約、根拠記事のリンク、トピック切替 |
| フィード | 記事一覧、絞り込み (カテゴリー、トピック、期間、ソース、検索、未読、スター)、既読とスターの操作 |
| 設定: ソース | 一覧、有効と無効の切替、最終取得時刻、エラー状態 |
| 設定: RSS追加 | URL、表示名、カテゴリーの入力、検証中、検証エラー |
| 設定: トピック | 一覧、追加と編集 (名前、キーワード) |
| 設定: LLM | 記事要約と期間要約のプロバイダー選択、Ollamaのモデル名、接続テストの結果 |
| 設定: スケジュール | 収集間隔、要約の時刻、ログイン時起動 |
| チャットパネル | 右側の開閉式パネル。文脈の表示、質問の入力、回答のストリーミング、ツール実行の表示、参照記事、スレッド一覧、LLM切替 |
| メニューバー | 今すぐ収集、ウィンドウを開く、終了 |
| 状態 | 要約の生成中、保留、失敗。記事なし。初回起動 (未収集)。ソースの取得エラー。チャットの空状態、生成中、エラー |

## ステップ

- [ ] **Step 1: 方向性の確認**

利用者に次を確認する。外観 (ライト、ダーク、両方)、情報密度 (一覧に多く出すか、余白を取るか)、参考にしたいアプリやサイト、ウィンドウの基準サイズ。回答をこのファイルの末尾「決定事項」に記録する。

- [ ] **Step 2: 画面構成 (ワイヤーフレーム)**

装飾なしで、ナビゲーション構造と主要3画面 (ダイジェスト、フィード、設定) の配置を作る。ナビゲーションの方式 (サイドバー、上部タブなど) は2案を並べて提示する。画像を書き出して利用者に見せ、構成の承認を得る。

- [ ] **Step 3: ビジュアルデザイン**

承認された構成に、色、文字、余白、コンポーネント (記事行、要約カード、フィルター、ボタン、入力欄、トグル) を適用する。デザイントークンを定義し、主要3画面に適用する。画像を書き出して利用者に見せ、調整と承認を繰り返す。

- [ ] **Step 4: 残りのフレームと状態**

設定の各タブ、RSS追加ダイアログ、メニューバー、状態フレーム (生成中、保留、失敗、記事なし、初回起動、取得エラー) を作る。Step 3 のコンポーネントとトークンを再利用する。画像を書き出して利用者に見せ、承認を得る。

- [ ] **Step 5: 整合性の確認**

全フレームを見直す。同じ要素の見た目と文言が画面間で一致していること、spec 7節の全機能がいずれかのフレームにあること、spec 8節にない項目を表示していないことを確認する。不一致を直す。

- [ ] **Step 6: spec への反映とコミット**

全フレームを `design/exports/` に書き出す。spec 7節を確定したデザインに合わせて更新する (レイアウト、トークン、構成要素)。データ項目や機能に変更がある場合は spec 8節と Plan 1 の該当タスクも更新する。変更点を利用者に報告し、最終承認を得てからコミットする。

```bash
git add design docs
git commit -m "docs: add screen design and update spec"
```

## 完了条件

- 利用者が全フレームを承認している。
- spec 7節が確定したデザインと一致している。
- デザインによるデータモデルや機能の変更が、spec と Plan 1 に反映されている (変更なしの場合はその旨を記録する)。

## 決定事項

### Step 1 (2026-10-06)

- 外観: ライトとダークの両方。macOSの設定に追従する。
- 情報密度: 中間。記事行はタイトル、ソース、日時、指標、要約1〜2行。1画面に8〜10件。
- 雰囲気: macOSネイティブ風。標準アプリに近いサイドバーと控えめな配色。
- ウィンドウの基準サイズ: 1200 x 800。小さくした場合の挙動も設計する。

### Step 2 (2026-10-06)

- ナビゲーション: サイドバー案を採用。上部タブ案は不採用とし、キャンバスから削除した。
- サイドバー: 「すべて」、カテゴリー7件、トピック、左下に収集状態と設定。各行に未読件数を表示する。
- 上部ツールバー: ダイジェストとフィードの切替。ダイジェストでは期間 (今日、週、月)、フィードでは期間、ソース、未読のみ、スターの絞り込みと検索。
- 設定: メインウィンドウ内に表示し、ソース、トピック、LLM、スケジュールをタブで切り替える。
- ワイヤーフレームは `design.pen` の A-1 (ダイジェスト)、A-2 (フィード)、A-3 (設定: ソース)。書き出しは `design/exports/wire-*.png`。
- specにない要素: フィードの「すべて既読にする」。採否は利用者の確認待ち。
- 構成を承認 (2026-10-06)。「すべて既読にする」を採用する (core に一括既読の関数を追加する。Step 6 で spec と Plan 1 に反映)。設定はメインウィンドウ内。ダイジェスト本文は1カラム。

### Step 3 (2026-10-06、確認待ち)

- デザイントークンを `design.pen` の変数に定義した。色はライトとダークの2値を持つ。
  - 背景: `bg-window`、`bg-sidebar`、`bg-subtle`。線: `border`。
  - 文字: `text-primary`、`text-secondary`、`text-tertiary`。
  - 強調: `accent`、`selection`、`on-accent`。状態: `success`、`danger`、`star`。
  - 部品: `seg-selected`、`toggle-off`。寸法: `radius-sm` 5、`radius-md` 7、`space-row` 12。
- 書体: pen 上は Noto Sans JP。実装ではmacOSのシステムフォント (日本語はヒラギノ角ゴ) を使う。
- 本文13px、補足11〜12px、画面見出し22px、節見出し15px。ダイジェストの要約は幅720pxに制限する。
- 主要3画面のライトとダークを作成した。書き出しは `design/exports/{1-digest,2-feed,3-settings-sources}-{light,dark}.png`。

### チャット追加 (2026-10-06)

- チャット (エージェント) 画面を追加した。spec 12節。LLMは Ollama と Claude (Nodeサイドカー)。ツールは記事検索、期間要約の参照、記事本文の取得、Web検索。配置は右パネル。会話履歴は保存する。
- フレーム A-4 (フィード + チャット) をライトとダークで作成した。書き出しは `design/exports/4-feed-chat-{light,dark}.png`。
- パネルは幅400px。上から、スレッド名と操作 (新規、履歴、閉じる)、文脈チップ、メッセージ (ユーザーは右寄せの吹き出し、エージェントはツール実行行、本文、参照記事)、入力欄 (モデル選択、送信)。
