# モバイルアプリ

InfoDesk のモバイルアプリ (Flutter、`mobile/`) は、Mac のアプリが書いた同期フォルダを読むためのアプリです。スマホでダイジェスト、フィード、記事を読めます。スマホで付けた既読とスターは Mac に、Mac で付けたものはスマホに届きます。アプリは日本語です。ビルドして動かしたのは iOS のシミュレーターだけです。

同期フォルダ、ファイル、保持期間は[クラウド同期](12-cloud-sync.ja.md)を、NAS 側は[NAS の準備](13-nas-setup.ja.md)を参照してください。

## 1. できること

- Mac が集めて要約したダイジェスト (今日、週、月)、記事のフィード、記事を表示します。
- スマホの中のデータベースに控えを持つので、ネットワークがなくても読めます。
- 既読とスターを付けます。印は同期フォルダに送られ、Mac の次の同期で Mac に届きます。Mac で付けた印は、スマホの次の同期で届きます。同じ記事を両方で変えたときは、新しい変更が勝ちます。
- 記事の収集も要約もせず、Mac が書いたものを書き換えません。Mac で同期をオンにしていないと、フォルダにはまだデータがありません。

## 2. 画面

下に浮いたバーに4つのタブがあります。ダイジェスト、フィード、スター、設定です。「デザインのモックアップ」と書いた画像はデザインファイルのもので、意図した配置を示します。シミュレーターのスクリーンショット2枚は、動いているアプリです。

### ダイジェスト

今日、週、月を切り替えます。期間の概観 (カテゴリーごとの件数、話題の強さ)、見出し、番号つきの要点と画像カード、根拠記事を表示します。下に引っ張ると同期します。右上にも同期のボタンがあります。

![ダイジェスト (デザインのモックアップ)](../design/exports/m1-mobile-digest.png)

### フィードとスター

小さな画像つきで記事を並べます。期間 (今日、3日、1週間、1ヶ月、すべて)、カテゴリーやトピック、「未読のみ」、スター、検索 (「記事を検索」) で絞れます。「さらに表示」で続きを読み込みます。「すべて既読にする」は、表示中の記事を既読にします。スターのタブは、スターを付けた記事だけのフィードです。下に引っ張ると同期します。

![フィード (デザインのモックアップ)](../design/exports/m2-mobile-feed.png)

### 記事

画像、カテゴリー、ソースと時刻、AI の要約、抜粋を表示します。上のバーに、スター、既読と未読の切り替え、共有 (リンクのコピー) があります。「記事を開く」は、アプリ内のブラウザ (iOS は SFSafariViewController) でページを開き、既読にします。このブラウザにはスターのボタンがないので、スターはこの画面で付けます。

![記事 (デザインのモックアップ)](../design/exports/m3-mobile-article.png)

### 設定

保存先の選択、Google のアカウントまたは Tailscale と NAS の入力欄、最終同期と Mac からの更新の時刻、「今すぐ同期」、端末内の控え (「控えを削除」)、アプリのバージョンがあります。

![設定 (デザインのモックアップ)](../design/exports/m4-mobile-settings.png)

## 3. 初回の起動と保存先の選択

最初の起動では、Mac がどこへ同期しているかを選びます。Mac と同じ保存先を選んでください。

![初回の起動 (デザインのモックアップ)](../design/exports/m5-mobile-first-launch.png)

![iOS シミュレーターでの初回の起動](images/mobile-first-launch.png)

- **Google ドライブ。** 「Google でログイン」を押し、Mac と同じ Google アカウントでログインします。使うのは Drive のアプリ専用の隠れた領域だけです (スコープ `drive.appdata`)。InfoDesk にパスワードは入力しません。
- **NAS (WebDAV)。** スマホは、アプリの中の Tailscale の端末を通して NAS につながります。Tailscale のアプリもシステムの VPN も要りません。「NAS (WebDAV)」を選び、次の順に進めます。
  1. 「Tailscale にログイン」を押します。ブラウザで Tailscale のページが開くので、NAS と同じアカウントでログインして端末を許可します。端末は Tailscale の管理画面に `infodesk-mobile` として現れます。tailnet で端末の承認がオンなら、管理画面で承認します。
  2. NAS の URL (`http://<NAS の名前>:5005/infodesk/`)、ユーザー名、パスワードを入れます。
  3. 「確かめる」を押します。アプリはフォルダの一覧を取り、成功すると「読み取れました」と出ます (Mac と違い、スマホはこの確認で一時ファイルを書きません)。

  NAS 側の準備 (WebDAV Server、共有フォルダ、ユーザー、NAS の Tailscale) は、[NAS の準備](13-nas-setup.ja.md)のとおり最初の1回だけ行います。アプリにも「NAS の準備を見る (初めての方へ)」に同じ5つの手順があります。

最初の同期は、ログイン後 (Google) か、「確かめる」が成功した後 (NAS) に始まります。その後はダイジェストが開きます。Mac がまだ同期していないときは、データがないことと、Mac で同期することを伝える表示が出ます。

![起動後のダイジェスト。Google の再ログインを求めている (iOS シミュレーター)](images/mobile-launch-relogin.png)

## 4. いつ同期するか

- アプリを開いたとき。
- バックグラウンドからアプリに戻ったとき。
- ダイジェストやフィードで下に引っ張ったとき。
- 設定の「今すぐ同期」(「同期」ボタン) か、ダイジェストの同期ボタンを押したとき。

同期は重なりません。同期中の要求は、その同期に合流します。ネットワークが切れていても何も失わず、次の同期でやり直します。

## 5. 書き込むもの

アプリは、Mac が書いたファイル (`manifest.json`、`meta.json.gz`、`day-*`、`digest-*`、`state-snapshot.json.gz`) を読むだけです。書くのは自分の変更の束 `ops-<端末 ID>-<時刻>-<連番>.json` だけで、既読とスターの変更が入ります。1回書いたら編集しません。フォルダの中のものを消したり上書きしたりはしません。記事の画像はフォルダに置かず、スマホが元のサイトから読みます。

## 6. 控えを削除する

設定の「控えを削除」(確認つき) は、スマホに保存した記事とダイジェストを消します。保存先のデータには触れず、次の同期ですべて取り直します。まだ送っていない印は失われるので、残したいときは先に同期してください。保存先を Google ドライブと NAS の間で切り替えたときも控えを消しますが、未送信の印は残します。NAS を選んでいる間に NAS の URL を変えたときも消します。

## 7. プライバシー

- Tailscale のログのアップロードはオフです。アプリ内の端末は Tailscale の「ログも支援もなし」の設定で起動するので、Tailscale へログを送りません。
- NAS のパスワードは、アプリの DB ではなく、iOS のキーチェーン (Android ではセキュアストレージ) に保存します。URL とユーザー名はアプリの DB にあります。
- Google のログインは Google 自身の画面で行うので、Google のパスワードを InfoDesk には入力しません。求める権限は `drive.appdata` だけです。
- Tailscale の状態 (端末の鍵) は、アプリのサポートフォルダの `tailnet` に保存し、端末のバックアップから除外します。除外できなかったときは Tailscale を起動せず、「Tailscale の状態をバックアップから除外できません」と出します。
- 同期のデータは、Google ドライブか、tailnet の中の NAS にだけ送ります。[プライバシーとセキュリティ](09-privacy-and-security.ja.md)を参照してください。

## 8. 困ったとき

アプリは次のメッセージを、同期の操作の近く、保存先の設定の下、または「確かめる」の結果として出します。

| メッセージ | 意味と対処 |
|---|---|
| 「Google の再ログインが必要です」 | Google のトークンが使えなくなりました。ダイジェストか設定で「Google でログイン」を押し直します。 |
| 「Google にログインできませんでした」 | ログインに失敗しました (閉じただけではありません)。もう一度試します。 |
| 「ネットワークに接続できません。次の同期で再試行します。」 | 保存先につながりません (ネットワーク、タイムアウト、HTTP 408、429、5xx)。何も失わず、次の同期でやり直します。NAS では、Tailscale の管理画面で NAS が接続中か、WebDAV Server がポート 5005 で動いているかを確かめます。 |
| 「同期フォルダにまだデータがありません。Mac で同期してください。」 | フォルダに `manifest.json` がありません。Mac で同期をオンにして、Mac で同期します。 |
| 「NAS のユーザー名かパスワードが違います」 | NAS が 401 を返しました。ユーザー名とパスワードを入れ直します。 |
| 「NAS のフォルダに書き込む権限がありません」 | DSM のユーザーに、共有フォルダの「読み取り/書き込み」がありません。 |
| 「NAS の空き容量が足りません」 | NAS のボリュームがいっぱいか、割り当てを超えています。 |
| 「NAS の URL を確かめてください (転送されました)」 | NAS が要求を転送しました。`http://<NAS の名前>:5005/<フォルダ>/` を、`http` とポート 5005 で使います。 |
| 「NAS の URL を確かめてください (例: http://takeuchi-nas:5005/infodesk/)」 | URL がホストつきの `http://` のアドレスではないか、ユーザー名やパスワードを含んでいます。 |
| 「http:// を使ってください (Tailscale の中なので暗号化されています)」 | URL が `https://` で始まっています。`http://` を使います。 |
| 「NAS が Tailscale の中に見つかりません。NAS の名前を確かめてください」 | URL のホストが tailnet の端末ではないので、何も送りませんでした。Tailscale の管理画面の NAS の名前か、`100.x.y.z` のアドレスを使います。 |
| 「NAS の URL、ユーザー名、パスワードを入力してください」 | NAS の3つの欄のどれかが空です。 |
| 「NAS のパスワードをキーチェーンに保存できません」 / 「NAS のパスワードを読めません」 | キーチェーンに書けないか読めません (ロック中など)。スマホのロックを解いてやり直します。 |
| 「Tailscale にログインしてください」 | アプリ内の端末がログインしていません。「Tailscale にログイン」を押します。 |
| 「Tailscale が停止中です」 | このスマホは前にログインしましたが、端末は止まっています。「Tailscale にログイン」を押して始めます。 |
| 「Tailscale の管理画面でこの端末を承認してください」 | 端末の承認がオンです。管理画面で `infodesk-mobile` を承認します。 |
| 「Tailscale のサーバーにつないでいます」 / 「ログインの準備をしています」 | 端末を始めています。30秒を過ぎると「もう一度試す」と「状態を消してやり直す」が出ます。 |
| 「起動できませんでした: …」 | 端末を始められませんでした。理由が続きます。「この端末の Tailscale の状態を消す」(確認つき) を押し、もう一度ログインします。管理画面の古い `infodesk-mobile` も削除します。 |
| 「Tailscale の状態を読めません。「状態を消してやり直す」を押してください」 | 保存した Tailscale の状態が使えません。ボタンで消してから、もう一度ログインします。 |
| 「Tailscale を初期化できません」 | このスマホで Tailscale を準備できませんでした。アプリを再起動します。ほかの理由で始められないときは、「起動できませんでした: Tailscale を起動できませんでした」と出ます (理由は日本語のときだけ表示します)。 |
| 「Tailscale の状態をバックアップから除外できません」 | 7節を参照。アプリを再起動します。 |
| 「保存先のエラー: …」 | そのほかの保存先のエラーです。コロンの後に詳細が続きます。 |
| 「記事を開けませんでした」 | 記事のページをブラウザで開けませんでした。 |
| 「処理に失敗しました。もう一度お試しください」 | 想定外の失敗です。もう一度試します。 |

同期は次の警告も出します。同期は止まりません。「manifest.json を読めませんでした」、「<ファイル> のハッシュが一致しないため取り込みませんでした」、「<ファイル> を読めませんでした」。

## 9. 開発者向けのビルド

コマンドの全体と理由は [`mobile/README.md`](../mobile/README.md) にあります。要点は次のとおりです。

- Flutter 3.44.7 (Dart 3.12.2) と Xcode 27。
- Flutter と Xcode は arm64 で動かします。シェルが Rosetta で動くときは、コマンドを `arch -arm64` で包みます。
- Go 1.26 以降を `PATH` に置きます。`tailscale` パッケージが、最初のビルドで Go を使ってネイティブのライブラリを作るためです。
- `ios/Flutter/Debug.xcconfig` と `Release.xcconfig` で `ARCHS[sdk=iphonesimulator*] = arm64` に固定しています。Xcode 27 の `lipo` が、flutter_tools の `-verify_arch arm64 x86_64` の検査を拒むためです。代わりに x86_64 のシミュレーターは使えません。
- iOS の Google のクライアント ID はコミットしません。Google Cloud Console からダウンロードした plist から、git 管理外の `ios/Flutter/Secrets.xcconfig` を作ります。`mobile/tool/ios_oauth_from_plist.sh <plist>`。
- シミュレーター: `flutter build ios --simulator --debug` のあと、`xcrun simctl` で `jp.infodesk.mobile` を入れて起動します。
- 実機には署名のチームが必要です。

## 10. 使う前の手動の確認

自動テストは偽の保存先を使うので、次の確認は利用者が行います。

1. Google (iOS シミュレーター): 「Google ドライブ」を選び、Mac のアカウントでログインして、同期でダイジェストとフィードが入ることを確かめます。
2. NAS: 「NAS (WebDAV)」を選び、スマホで Tailscale にログインします。求められたら管理画面で `infodesk-mobile` を承認します。URL とユーザーを入れて「確かめる」を押し (「読み取れました」が出ること)、同期してデータが入ることを確かめます。
3. スマホから Mac: スマホで記事を既読にしてスターを付け、スマホで同期し、Mac で「今すぐ同期」を押して、Mac に印が出ることを確かめます。
4. Mac からスマホ: Mac で別の記事を既読にしてスターを付け、Mac で同期し、スマホで下に引っ張って、印が出ることを確かめます。

Mac の同期のキーは[設定](07-settings.ja.md)を参照してください。
